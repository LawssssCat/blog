好处：
- 加速部署 —— 通过容器构建避免重复部署复杂机器学习环境
- 提升资源利用率 —— 统一调度和分配集群资源
- 保障资源独享 —— 利用容器隔离异构设备，避免相互影响

## 示例

步骤：
1. 构建包含模型训练和推理工具的镜像
2. 将**GPU设备（驱动）**和**依赖库**映射到容器中

容器镜像 —— 简化操作

- nvidia/cuda
- tensorflow/tensorflow

Docker 映射 NVIDIA

```bash
docker run -it \
--volume=nvidia_driver_xxx.xx:/usr/local/nvidia:ro \
--device=/dev/nvidiactl \
--device=/dev/nvidia-uvm \
--device=/dev/nvidia-uvm-tools \
--device=/dev/nvidia0 \
nvidia/cuda nvidia-smi 
```

K8S 映射 NVIDIA （通过 Nvidia Device Plugin 集成）

```bash
# 安装驱动
sudo yum install -y gcc kernel-devel-$(uname -r)
sudo /bin/sh ./NVIDIA-Linux-x86_64*.run

# 安装 NVIDIA Docker2
sudo yum install nvidia-docker2
jsudo pkill -SIGHUP dockerd
$ cat daemon.json
{
  "default-runtime": "nvidia",
  "runtimes": {
    "nvidia": {
      "path": "/usr/bin/nvidia-container-runtime",
      "runtimeArgs": []
    }
  }
}

# 部署 Nvidia Device Plugin
kubectl create -f nvidia-device-plugin.yml
$ cat nvidia-device-plugin.yml
apiVersion: v1
kind: Pod
metadata:
  name: cuda-vector-add
spec:
  restartPolicy: OnFailure
  containers:
    - name: cuda-vector-add
      image: "nvidia/cuda-vector-add:v0.1"
resources:
  limits:
    nvidia.com/gpu: 1 # 重要：这里声明之后，会自动将驱动挂载
$ kubectl get pod -l component=nvidia-device-plugin # 查看容器部署情况
$ kubectl exec -it gpu -- nvidia-smi # 查看容器内部，显卡识别情况
```

## 原理

通过如下接口实现：

- Extend Resources —— 通过自定义资源扩展，允许用户分配和使用 non-Kubernetes-built-in 的计算资源。
  - 缺点： 只支持整数资源分配，比如一个容器只要使用GPU则需要整块分配。为弥补该问题，有vNPU虚拟化技术。
- Device Plugin Framework —— 允许第三方设备提供商以插件外置的方式对设备的调度和全生命周期管理。

```bash
# 手动 Extend Resource 上报
$ curl --header "Content-Type: application/json-patch+json" \
--request PATCH \
--data '[{"op":"add","path":"/status/capacity/nvidia.com/gup","value":"1"}]' \
https://localhost:6443/api/v1/nodes/<your-node-name>/status

# 通过 Device Plugin Frame 自动管理将自动上报
resources:
  limits:
    nvidia.com/gpu: 1
```
